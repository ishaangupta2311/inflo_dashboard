PayPal Webhook and Checkout Recovery

Make PayPal checkout recoverable when payment succeeds but the browser callback or subsequent database work fails.

Outcome

The application will persist an authenticated checkout before creating a PayPal order. Either the browser capture callback or a verified PayPal webhook can then finalize that checkout exactly once. The server remains authoritative for cart pricing and order creation.

Architecture

1. Prepare
Persist user, cart, brief, amount, and currency before calling PayPal.
2. Capture
Use the stored checkout for browser-triggered capture and amount verification.
3. Reconcile
Verify webhook signatures and finalize the same checkout after completed captures.

Persistent checkout

Add a PayPalCheckout model with a generated local ID, user ID, serialized cart lines, brief, expected amount, currency, unique PayPal order ID, optional capture ID, state, paid timestamp, last event type, and timestamps. States are string values: pending, approved, paid, denied, refunded, and failed.

The PayPal order's custom_id will contain the local checkout ID. The normal lookup uses the unique PayPal order ID; custom_id provides a recovery link if PayPal order creation succeeds but saving its ID locally fails.

Shared finalization

A server-only finalizer will load the persisted checkout, validate the captured USD amount, and call the existing idempotent order creation path using the PayPal order ID as the payment reference. Browser and webhook handlers will both use this function. A previously paid checkout returns success without creating new orders or sending duplicate email.

Request Flows

Create order

  1. Require Clerk authentication and validate/price cart lines on the server.
  2. Create a pending checkout record with the authoritative amount.
  3. Create the PayPal order with the local checkout ID in custom_id.
  4. Save the PayPal order ID and return it to the browser.

Browser capture

  1. Require Clerk authentication and load the checkout by PayPal order ID and user ID.
  2. Capture through PayPal, then validate status, currency, and amount.
  3. Finalize from persisted cart data and return the created order count.

The browser will no longer resubmit cart lines or the brief during capture.

Webhook

  1. Read the event and PayPal transmission headers.
  2. Post the event and configured webhook ID to PayPal's signature-verification endpoint.
  3. For PAYMENT.CAPTURE.COMPLETED, resolve the PayPal order ID, validate amount/currency, and finalize.
  4. For denied and refunded captures, update the checkout state. Approved orders record the approved state.
  5. Return a successful response for supported, verified duplicate events.

Event Contract

PayPal eventApplication action
CHECKOUT.ORDER.APPROVEDMark the persisted checkout approved when it has not already advanced.
PAYMENT.CAPTURE.COMPLETEDValidate amount and currency, then finalize paid orders idempotently.
PAYMENT.CAPTURE.DENIEDMark the checkout denied; do not create orders.
PAYMENT.CAPTURE.REFUNDEDMark the checkout refunded and mark linked orders refunded.

Security and Failure Handling

  • Require PAYPAL_WEBHOOK_ID; never accept an unverified webhook.
  • Use PayPal OAuth and signature verification against the same sandbox/live environment as checkout.
  • Reject missing or invalid verification headers with 401.
  • Return 500 for temporary processing failures so PayPal retries delivery.
  • Return 200 for verified irrelevant or already-processed events.
  • Never trust client-submitted prices, ownership, payment state, or webhook event names without verification.
  • Log event IDs and PayPal order IDs, but not credentials or complete sensitive payloads.

Configuration and Migration

Add PAYPAL_WEBHOOK_ID to .env.example and the Vercel Production environment. Apply the Prisma migration that creates the checkout table before deploying application code that writes to it.

Verification

  • Valid completed capture creates paid orders from the persisted cart.
  • Repeated callback and webhook delivery create no duplicate orders or emails.
  • Webhook recovery succeeds when the browser callback is absent.
  • Invalid signatures and missing headers cannot change payment state.
  • Captured amount or currency mismatch does not create orders and is logged for investigation.
  • Denied and refunded captures update state without creating new orders.
  • Existing non-PayPal checkout behavior remains unchanged when PayPal is not configured.

Deployment Order

  1. Apply the database migration.
  2. Add PAYPAL_WEBHOOK_ID in Vercel alongside the existing PayPal credentials.
  3. Deploy the application route at /api/paypal/webhook.
  4. Register https://app.influenceroutreachsolutions.com/api/paypal/webhook in the matching PayPal Live app.
  5. Run one sandbox end-to-end payment and resend its event to verify idempotency.
